# Clueless's server (Supabase)

Students sign in to Clueless, and Claude runs on our key, here, never on their laptop.

| Piece | What it does |
|---|---|
| `migrations/20261105120000_voice.sql` | Voice usage: voice messages and read-aloud characters per week, counted in `usage_events`. |
| `functions/voice/` | Voice with no keys on the laptop: a 30-second Deepgram token for each recording, and ElevenLabs read-aloud when it's switched on. |
| `migrations/20261104120000_history.sql` | History: `sessions` (one row per problem, text only) and `session_secrets` (the hidden solution and full plan, which students can save through `save_secrets()` but never read). |
| `migrations/20261103120000_accounts.sql` | Tables: `profiles`, `invite_codes`, `plan_limits`, `usage_events`. Functions: `activate()` (invite code + 18+), `usage_check()` and `my_usage()` (this week's use). Students can read only their own rows. |
| `functions/ai/` | The Claude proxy. The app's Anthropic SDK points here. It checks the sign-in, the job and the weekly caps, then picks the model. It calls Claude with our key and records the tokens and cost. |
| `functions/_shared/` | The proxy's logic, plain TypeScript. The app's tests run this same code (`app/src/main/account/*.test.ts`). |
| `functions/_shared/allowlist.ts` | Fingerprints of the app's prompts and reply schemas, so our key only runs Clueless requests. Generated by `npm run allowlist`. |
| `config.toml` | Sign-in settings: Google, email links, and the app's redirect URLs. |

Weekly caps for the beta: 20 problems, 60 Asks, $2 of Claude, and 30 requests a minute per student. Weeks reset Monday 00:00 New York time. Change the caps in `plan_limits`; no app release is needed.

## Going live (once the Supabase account exists)

The quick way: fill in `.env` in the repo root (each line says where its value comes from), then run
`scripts/go-live.sh`. It does steps 2 to 8 below, and puts the website on Vercel. The steps are here
for doing them by hand.

You run these. Each step is a few minutes.

1. **Create the project** at supabase.com: region US East, free plan. Note the project ref (the `xxxx` in `xxxx.supabase.co`).
2. **Link and push the database** from the repo root:
   ```bash
   supabase login
   ```
   ```bash
   supabase link --project-ref xxxx
   ```
   ```bash
   supabase db push
   ```
3. **Claude key.** Create an API key in the Anthropic Console (console.anthropic.com), on an organization with billing. Set a monthly spend limit there too. Then:
   ```bash
   supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
   ```
   Optional: `CLUELESS_TUTOR_MODEL` and `CLUELESS_FAST_MODEL` (defaults: `claude-sonnet-5-5`, `claude-haiku-5-5`).
4. **Deploy the proxy:**
   ```bash
   supabase functions deploy ai
   ```
5. **Google sign-in.**
   - In Google Cloud Console, open APIs & Services → Credentials and create an OAuth client of type "Web application".
   - Set its authorized redirect URI to `https://xxxx.supabase.co/auth/v1/callback`.
   - Then push the sign-in settings. This also sets the app's redirect URLs.
   ```bash
   SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID=... SUPABASE_AUTH_EXTERNAL_GOOGLE_SECRET=... supabase config push
   ```
6. **Email that arrives.** Supabase's built-in email sends only a few messages an hour, which is too few for a class. Set up custom SMTP: dashboard → Authentication → Emails → SMTP, for example with Resend.
7. **Invite codes.** In the dashboard's SQL editor:
   ```sql
   insert into public.invite_codes (code, note, max_uses) values ('LEHIGH-TA', 'TA class, fall', 60);
   ```
8. **Point the app at it.** Put the project URL and the publishable key (Settings → API Keys) in `app/src/main/account/project.ts`. The publishable key is safe to ship in the app.
9. **Try it.** Take the Claude and AWS keys out of `app/.env` (or set `CLUELESS_PROVIDER=clueless`), run `npm run dev`, then sign in and solve a problem.

## Voice

- **Talking to Clueless** needs `DEEPGRAM_API_KEY` as a function secret. The key must have the
  **Member** role (Deepgram → API Keys), since it hands out short-lived tokens.
- **Reading aloud** uses the student's own computer voice during the beta. To switch ElevenLabs on,
  set these secrets: `CLUELESS_ELEVENLABS=on`, `ELEVENLABS_API_KEY`, and `CLUELESS_ELEVENLABS_VOICE`
  (a voice ID from your ElevenLabs account). The app picks it up within ten minutes, with no release.
- **Weekly caps:** `plan_limits.listens_per_week` (300) and `speech_characters_per_week` (20,000).

## Running it

- **Changed a prompt or a reply schema?** Run `npm run allowlist` in `app/`, then `supabase functions deploy ai`. Until then the server refuses the new prompt. The test `allowlist.test.ts` fails as a reminder.
- **Ban a student:** `update public.profiles set banned = true where id = '...';`
- **Cost per student this week:**
  ```sql
  select p.id, u.email, count(*) filter (where e.unit = 'problem') as problems, round(sum(e.cost_usd), 2) as dollars
  from public.usage_events e
  join public.profiles p on p.id = e.user_id
  join auth.users u on u.id = p.id
  where e.created_at >= public.week_start()
  group by p.id, u.email order by dollars desc;
  ```

## Trying it without the cloud

- `npm test` in `app/` runs `e2e.test.ts`. It signs a student in with an email link and enters an invite code. Then the real Tutor and Tracer call Claude through the real proxy code, against a fake Supabase and a fake Claude.
- The SQL was checked on PGlite (Postgres in Node) with stand-ins for Supabase's `auth` schema.
- `supabase start` runs the whole stack locally, but it needs Docker.
